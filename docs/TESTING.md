# 个人主页 测试规范

> 用途：给改完页面要验证的人。本仓没有测试框架与 lint（有意为之，见 `docs/ARCHITECTURE.md`）；
> CI 只有跑两条核对命令的最小工作流（`.github/workflows/check.yml`），门禁是两条核对命令加目检。

## 测试分层

| 层 | 管什么 | 怎么做 |
|---|---|---|
| 静态核对 | 图片引用与锚点完整性 | 「资源核对」「锚点核对」两条命令，原文在 `AGENTS.md`「当前状态」 |
| 目检 | 排版与响应式 | `python -m http.server 8000` 打开，桌面与 ≤640px 各看一眼 |
| 线上核对 | 发布是否生效 | `curl -s https://luz7818.github.io/ \| wc -c` 与本地 `index.html` 字节数比对 |

两条核对命令的判读：**资源核对输出为空** = 页面引用到的图片与磁盘上的完全一致（`assets/README.md`
是文档、不上页面，命令里已滤掉）；**锚点核对输出为空** = 每个 `href="#…"` 都有对应 `id`。
命令正文只保留在 `AGENTS.md` 一份，这里不复述，防止口径漂移——两个 grep 的原始输出口径不同，
不能直接 diff，粘贴时以 `AGENTS.md` 那份为准。

## 用例编写规范

无测试框架。发现新的可自动核对项时，写成一条可直接粘贴的命令登记进 `AGENTS.md`「当前状态」，
不要为此引入测试依赖。

## 改动后的验证

| 动了什么 | 必须做 |
|---|---|
| 文案/样式/结构 | 本地目检一遍；移动端宽度（≤640px）也看一眼 |
| 新增或替换图片 | 跑资源核对，输出为空 |
| 新增小节或改导航 | 跑锚点核对，输出为空 |
| 任何改动 | `git push` 后 `curl -s https://luz7818.github.io/ \| wc -c` 确认线上字节数已变 |
